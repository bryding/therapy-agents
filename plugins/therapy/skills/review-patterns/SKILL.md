---
name: review-patterns
description: Periodic review of context/patterns.md against recent evidence. The only sanctioned path to editing patterns.md. Use when the owner says "review patterns", "is this still a pattern", "I think there's a new pattern", or roughly monthly.
---
Audit `context/patterns.md` against material since the last review (git log
on patterns.md): session summaries, journal digest, check-ins, letters.

For each pattern: **evidence for** (dated, cited), **evidence against** or
counter-examples, **verdict**: live / improving / dormant / retire. Improving
needs a real counter-example, not just an absence of incidents.

Then:
- **Candidates**: only if a pattern shows up in at least two separate
  documents. One-off events are events.
- **Self-indictment the evidence doesn't support.** Push back on that too.

Present the whole review before touching anything. Edit patterns.md only with
explicit sign-off per change. Keep numbering stable (retired patterns get
"(retired YYYY-MM)"). Date the review at the bottom. Commit.
